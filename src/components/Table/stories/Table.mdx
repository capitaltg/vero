# Table

> **Preview.** Both components are complete and covered by tests, but they are not exported from
> the published package yet — uncomment them in `src/index.ts` to ship them.

Accessible, 508-friendly tables styled after the
[USWDS Table](https://designsystem.digital.gov/components/table/), with sorting, column grouping
and responsive behavior built on [TanStack Table](https://tanstack.com/table).

Vero ships two components over one render layer:

      </td>
    </tr>
  </tbody>

Don't mix the two inside one table: either compose the primitives yourself, or drive a
`DataTable` and customize it through its seams (`ColumnDef.cell` renderers, `meta`, and the
`caption` / `footer` / `emptyState` slots).

## Quick start

```tsx
import { Table, TableBody, TableCell, TableHead, TableHeader, TableRow } from '@capitaltg/vero';

<Table caption="Quarterly revenue">
  <TableHeader>
    <TableRow>
      <TableHead scope="col">Quarter</TableHead>
      <TableHead scope="col">Revenue</TableHead>
    </TableRow>
  </TableHeader>
  <TableBody>
    <TableRow>
      <TableHead scope="row">Q1</TableHead>
      <TableCell>$1.2M</TableCell>
    </TableRow>
  </TableBody>
</Table>;
```

The `caption` prop is a convenience for the common case; compose `<TableCaption>` yourself when
the caption needs its own markup.

The same table, config driven:

```tsx
import { DataTable } from '@capitaltg/vero';
import type { ColumnDef } from '@tanstack/react-table';

interface Person {
  name: string;
  role: string;
  salary: number;
}

const columns: ColumnDef<Person, unknown>[] = [
  // One column per table should be the row header.
  { accessorKey: 'name', header: 'Name', meta: { isRowHeader: true } },
  { accessorKey: 'role', header: 'Role' },
  {
    accessorKey: 'salary',
    header: 'Salary',
    meta: { align: 'right' },
    cell: info => `$${info.getValue<number>().toLocaleString()}`,
  },
];

<DataTable caption="Team roster" columns={columns} data={people} />;
```

Every table needs an accessible name. Prefer a visible `caption`; if a heading beside the table
already names it, pass `captionHidden` to keep the caption for screen readers only, or use
`aria-label`.

## `Table` props

<Controls of={TableStories.Playground} />

Alongside `caption` / `captionHidden`, `Table` takes the styling and responsive props shared with
`DataTable`: `variant` (`bordered` | `borderless`), `striped`, `density` (`default` | `compact`),
`stickyHeader`, `responsive` (`scroll` | `stack` | `none`), `stackBreakpoint` (`sm` | `md` | `lg`)
and `stackedStyle` (`default` | `headers`). Everything else lands on the `<table>` element.

The children are thin wrappers over the native elements: `TableCaption` (`<caption>`, with
`hidden` for a screen-reader-only caption), `TableHeader` (`<thead>`), `TableBody` (`<tbody>` —
use several for row-group sections), `TableFooter` (`<tfoot>`), `TableRow` (`<tr>`), `TableHead`
(`<th>`, with `scope` defaulting to `col`) and `TableCell` (`<td>`). Both cell components accept
`data-label`.

## Responsive behavior

This is the part you get for free, and it works the same on both components.

### Scrolling — the default

Wide tables get a horizontal scroll container. It only becomes a focusable, labeled
`role="region"` when the content actually overflows, so a table that fits never adds a stray tab
stop, and one that doesn't fit stays reachable by keyboard.

<Canvas of={DataTableStories.Scrollable} />

Unlike USWDS we don't force `white-space: nowrap` on cells, so text wraps by default and narrow
tables simply get narrower. Add `whitespace-nowrap` to the columns that should never be squeezed.

### Stacking into cards

With `responsive="stack"`, each row below `stackBreakpoint` becomes a card and every cell renders
its column header above its value. Resize your browser below 768px to watch these reflow — the
docs canvas is rendered at the page's own width.

<Canvas of={DataTableStories.Stacked} />

The label comes from a `data-label` attribute on each cell, rendered as
`content: attr(data-label)` — the same mechanism USWDS uses. You never have to write it:

- `DataTable` fills `data-label` in from your column definitions (or `meta.stackedLabel`).
- `Table` reads the header row and labels the body cells below it, so hand-composed tables stack
  too. An explicit `data-label` on a cell always wins.

Two things to know before choosing this mode. Below the breakpoint the header row is hidden, so
the grid's row/column semantics give way to the card layout and the per-cell labels carry the
meaning — that also means sortable headers are only reachable at wider widths. It suits
record-style data; for wide numeric tables, `responsive="scroll"` keeps the grid intact.

### Cards with headings

`stackedStyle="headers"` promotes the first cell of each row to the card's heading instead of
labeling it like the rest — good when that first column identifies the record.

<Canvas of={DataTableStories.StackedHeaders} />

### Sticky header

`stickyHeader` keeps the column headers visible while the rows scroll. The table needs a scrolling
ancestor for that: the page itself, or a height-constrained container. Pair it with
`responsive="none"` so the default horizontal scroll wrapper doesn't become a non-scrolling sticky
context. USWDS advises against combining it with scrollable or stacked variants.

<Canvas of={DataTableStories.StickyHeader} />

## Accessibility

- Every table has an accessible name — a `<caption>`, `captionHidden`, or `aria-label`.
- Column headers are `<th scope="col">`, group headers `scope="colgroup"`, and the column marked
  `meta.isRowHeader` renders `<th scope="row">`.
- Sortable headers are buttons inside the `<th>`; the `<th>` carries
  `aria-sort="ascending | descending | none"` and changes are announced politely.
- The scroll container becomes `role="region"` with `tabindex="0"` and a visible focus ring only
  when it actually scrolls, so keyboard users can reach off-screen columns without a phantom tab
  stop on tables that fit.
- Stacked mode labels every cell with its column header, so the data stays perceivable once the
  header row is hidden.
- Every state above is covered by `vitest-axe`. Stacked mode trades table semantics for the card
  layout by design — a manual screen-reader pass is still worth doing for your specific content.
