<DocsWhenToUse>

<DocsWhenToUseCard kind="use">

- **When users need to know where they are** in a site with several levels, especially if they
  may arrive on an inner page from a search or a link.
- **To show how a site is organized**, and let users move up to a parent page in one step.

</DocsWhenToUseCard>

<DocsWhenToUseCard kind="avoid">

- **A simple or flat site**, where the main navigation already shows where the user is: leave
  breadcrumbs out.
- **The home page, and often top-level landing pages**, where the place in the hierarchy is
  obvious: leave them out.
- **Side navigation that already shows the path:** breadcrumbs may repeat it.
- **Steps in a process**, such as a multi-page form: use a
  [StepIndicator](?path=/docs/actions-navigation-stepindicator--docs). Breadcrumbs show a
  hierarchy, not progress.

</DocsWhenToUseCard>

</DocsWhenToUse>

<DocsSubheading id="usability">Usability guidance</DocsSubheading>

- **Use the pages' titles**, worded as they are on each page, so users recognize where a link
  goes.
- **Start with "Home" as text.** An icon can sit beside it, but don't use a house icon on its
  own.
- **End with the current page, without an `href`.** It's shown as plain text and marked as the
  current page.
- **Keep labels short.** A long trail wraps onto more lines, which is harder to scan on small
  screens. For a very deep site, consider showing only the parent page on narrow screens.
- **Use one style of separator** across the site. The default chevron is a good choice.
- **Add structured data for search engines yourself** if you want breadcrumbs in search
  results: Breadcrumbs doesn't output JSON-LD or RDFa.

</DocsSection>

<DocsSubheading id="built-in">Built in</DocsSubheading>

- **It's a navigation landmark**: a `<nav>` named "Breadcrumb", so screen reader users can jump
  to it. Pass your own `aria-label` to rename it.
- **The items are an ordered list**, so screen readers announce how many there are and where
  each one sits.
- **The current page is marked `aria-current="page"`.** An item without an `href` is rendered as
  text, not a link, and screen readers announce it as the current page.
- **Links are native `<a>` elements**, in the tab order, with the browser's focus outline.
- **The default chevron separator is hidden from screen readers.**
- **Contrast:** links are 6.7:1 against white, the current page 17.2:1 and the separators 5.3:1,
  above the 4.5:1 that WCAG requires for text.

<DocsSubheading id="your-responsibility">Your responsibility</DocsSubheading>

- **Give every item except the last an `href`.** Any item without one is marked as the current
  page.
- **Hide a custom `separator` from screen readers.** For now, only the default chevron is
  hidden: a text separator such as `/` is read between every link
  ([#218](https://github.com/capitaltg/vero/issues/218)). Wrap it in a hidden span:

  ```tsx
  <Breadcrumbs items={items} separator={<span aria-hidden="true">/</span>} />
  ```

- **Keep text in icon items.** An item whose `label` is only an icon has no name. Keep the text,
  as in the icons example, or add a visually hidden label.
- **Use one breadcrumb trail per page**, so there's one landmark named "Breadcrumb". Give your
  page's other `<nav>` landmarks names of their own.
- **Test it in your page.** Run the
  [USWDS breadcrumb accessibility tests](https://designsystem.digital.gov/components/breadcrumb/accessibility-tests/)
  on your own page, including a screen reader pass.

For an accessibility review, see
[all open accessibility issues for Breadcrumbs](https://github.com/capitaltg/vero/issues?q=is%3Aopen+label%3Aa11y+in%3Atitle+Breadcrumbs).
